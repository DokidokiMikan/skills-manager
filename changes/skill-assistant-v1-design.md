# Skill 助手 V1 设计说明

## 背景

Skill 助手的目标不是简单列出本地 Skill，而是让模型更准确地理解本地 Skill 库：知道每个 Skill 适合什么、不适合什么、和相似 Skill 的差异，以及在用户咨询时给出可靠的推荐。

旧版 Skill 助手已经验证过一种有效方向：稳定的 Skill 外壳加可更新的 `data/` 数据部分。新的 V1 继续沿用这个思路，但收窄范围，先只做咨询型 Skill 助手，暂不做 Agent 自动路由。

## V1 目标

- 生成一个可以交给大模型使用的 Skill 助手 Skill。
- 支持咨询、推荐、对比、解释本地 Skill 库中的 Skill。
- 本地 Skill 库变化后，提示用户确认更新助手数据。
- 保持数据更新轻量，避免每次全量重建。
- 为未来 Agent 模式预留数据结构，但不在 V1 实现 Agent 自动调用。

## 非目标

- 不做 Agent 自动路由或自动调用 Skill。
- 不做后台静默全自动更新。
- 不强制对全库进行模型语义增强。
- 不把旧版 Skill 助手页面原样搬回。
- 不做复杂知识图谱或大规模可视化。

## 生成物形态

V1 生成两类产物：

- 可编辑目录：`skill-assistant/`
- 可分享压缩包：`skill-assistant.zip`

目录用于日常查看、调试和局部更新；压缩包用于备份、迁移和分享。

推荐结构：

```text
skill-assistant/
  SKILL.md
  data/
    manifest.json
    index/
    cards/
    groups/
  references/
  scripts/
```

## 数据架构

继续保留 `data/`，但从单个大文件拆成更细的分片和索引：

- `data/manifest.json`：记录数据版本、生成时间、Skill 库来源、文件映射和兼容信息。
- `data/index/`：基础索引，用于快速候选筛选。
- `data/cards/`：每个 Skill 一个卡片文件，保存基础信息和可选语义增强结果。
- `data/groups/`：分类、家族、相似 Skill 分组，用于对比和咨询。
- `references/`：稳定的助手规则、回答原则、更新说明和边界说明。
- `scripts/`：可选检索脚本，帮助 Skill 在数据量较大时查找候选。

这个结构的核心原则是：Skill 外壳稳定，数据可局部刷新。新增或修改某个 Skill 时，优先只更新对应卡片和受影响的索引。

## 更新策略

采用“检测变化后提示确认”的方式：

1. 扫描本地 Skill 库，计算 Skill 文件状态。
2. 和 `manifest.json` 中记录的状态对比。
3. 如果发现新增、删除或修改，提示用户存在可更新内容。
4. 用户确认后，只刷新受影响的数据分片。
5. 更新完成后重写 `manifest.json`。

这样比后台自动更新更可控，也比完全手动重建更轻。

## 语义增强策略

采用混合方案：

- 基础索引必做：本地解析 Skill 名称、描述、路径、关键词、文件结构等，不依赖模型。
- 语义增强可选：对新增、修改或用户手动选择的 Skill 调用模型生成增强卡片。
- 助手回答优先级：增强卡片优先，其次基础索引，最后参考原始 `SKILL.md` 摘要。

语义增强不再作为一个很重的独立主功能，而是作为数据生成管线中的增强步骤。

## 增强卡字段

每个 Skill 卡片建议包含：

- `summary`：一句话用途说明。
- `best_for`：最适合的任务或场景。
- `not_for`：不适合的任务或场景。
- `trigger_signals`：用户请求中可能触发该 Skill 的意图、词汇和任务形态。
- `anti_triggers`：容易误触发但不应该使用该 Skill 的情况。
- `capabilities`：该 Skill 能做什么。
- `limitations`：能力边界和限制。
- `similar_skills`：容易混淆或需要比较的 Skill。
- `routing_notes`：推荐、排除和组合使用时的判断说明。

## 助手回答风格

默认采用顾问分析型，但不固定死模板。回答应根据用户问题调整：

- 用户问“该用哪个”时，先给结论。
- 用户问两个 Skill 的区别时，重点对比。
- 用户问为什么不用某个 Skill 时，重点解释边界和不推荐原因。
- 用户问题很宽泛时，先给候选，再说明需要补充哪些信息才能更准确。
- 用户只想查用途时，简短回答。

底层原则是“先帮助决策，再解释依据”，而不是每次机械输出同一套格式。

## 风险与控制

- 模型增强可能误读 Skill 能力，需要保留基础索引和原始来源，避免只依赖生成文本。
- 首次增强全库可能较慢，因此 V1 默认只做基础索引，增强按需触发。
- 相似 Skill 对比依赖分类和分组质量，V1 先做轻量分组，不追求复杂知识图谱。
- Agent 模式暂不实现，避免过早把咨询逻辑和自动执行逻辑绑死。

## 后续预留

V1 的数据结构为 Agent 模式预留以下可能性：

- 复用 `trigger_signals` 和 `anti_triggers` 做候选筛选。
- 复用 `routing_notes` 做调用建议。
- 复用 `groups/` 做多 Skill 组合判断。
- 后续新增面向 Agent 的轻量输出格式，但不影响 Skill 助手的咨询体验。
